# PENDING_EXPORTS

Binary artifacts in this repo used to be hand-exported, so a number that changed in
`eval/results.json` reached the markdown automatically and reached the PDFs and the slide deck
only when a human re-exported them. This file is the running list of what is currently stale.
**A stale binary is the single easiest way to say a number on stage that does not match the one
on the screen**, which is the failure `docs/RUBRIC_ATTACK.md`'s cross-artifact numbers sweep
exists to catch.

Clear an entry by re-exporting and deleting the line, not by editing this file's dates.

## How to regenerate, in order

```bash
make eval        # only if results.json needs rebuilding; it does not today
python3 scripts/fill_numbers.py   # docs/templates/*.md -> docs/*.md, README.md, NUMBERS.json
make deck        # ppt/Pramaan_SIH2026_Idea.pptx from results.json
python3 scripts/export_pdfs.py    # every docs/*.pdf, then ppt/Pramaan_SIH2026_Idea.pdf
```

Nothing here is by hand any more. `scripts/export_pdfs.py` renders each markdown file to HTML
and prints it with headless Chrome, which is what produced the PDFs already in the repo
(`Skia/PDF`, `HeadlessChrome` in their metadata), and converts the deck with headless
LibreOffice, which is what produced the deck PDF (`LibreOffice` as its producer). It needs the
`markdown` package (`pip install markdown`), Google Chrome, and `soffice`; it stops with the
reason if any of the three is missing.
