
==============================================================================
STEP 0 · THE AUDIO   clone_xtts_v2.wav
==============================================================================
64000 samples at 16000 Hz = 4.00 seconds of sound
each sample is loudness at one instant, between -1 and +1:
  first 12 : [ 0.002  0.002  0.002 -0.    -0.001 -0.    -0.001  0.    -0.001 -0.    -0.002 -0.001]
  loudest  : 0.876     average level: 0.1616

That is all the computer has. 64,000 numbers. Nothing about words or voices yet.

==============================================================================
STEP 1 · THE FROZEN MODEL   facebook/wav2vec2-xls-r-300m
==============================================================================
It has 315 million numbers inside, and none of them change.
It chops the 4 seconds into 199 overlapping frames, one every 20 ms,
and describes each frame with 1024 numbers.
It produces 25 stages of description. We read stage 5.

So stage 5 is a table of 199 rows x 1024 columns = 203,776 numbers.
  frame 0, first 10 of its 1024 numbers : [-1.453 -6.983  0.618 -0.064 -3.09  -1.53   0.64  -0.439  0.93  -2.963]
  frame 1, first 10                     : [-0.474 -3.561  1.845  0.161 -1.376 -0.426  1.563 -0.342  2.908  1.052]
  frame 100, first 10                   : [-2.31  -1.297  0.681  1.745  0.318  1.538  0.606  3.081 -1.406  0.974]

These are LEARNED features, not hand-designed ones. Nobody can point at column 37
and say 'that is pitch'. The model invented them while learning 128 languages.
What matters is that machine-made speech puts different values in them than a
human throat does, and that difference survives a phone line.

Why stage 5 of 25: the early stages still describe HOW the sound was made
(texture, breath, micro-timing). The last stages have thrown that away and only
kept WHAT was said, which is useless for spotting a fake.

==============================================================================
STEP 2 · SQUASH THE TABLE INTO ONE ROW
==============================================================================
A call has no fixed length, so we summarise the 199 frames two ways:
  the AVERAGE of each column  -> 1024 numbers  (the typical texture of this voice)
  the SPREAD  of each column  -> 1024 numbers  (how much it varies: humans vary more)
  glued together              -> 2048 numbers, and this is the whole clip now

  average, first 8 : [-0.238  0.647  1.379  0.756  0.476  0.953  0.405  0.656]
  spread,  first 8 : [1.516 2.909 1.212 1.7   1.115 1.215 1.351 2.13 ]

  So 64,000 audio samples became 2048 numbers. This is the only thing the
  classifier ever sees.

==============================================================================
STEP 3 · OUR CLASSIFIER
==============================================================================
It is 2,049 numbers: one weight per feature, plus one bias.
It works in two moves.

  Move 1, put every feature on the same scale, using the average and spread
  measured across the whole training set:
    raw feature 0    : -0.238
    training average : +0.196   training spread: 0.475
    so scaled        : -0.914  (how unusual this clip is on that feature)

  Move 2, multiply each scaled feature by its weight and add everything up:
    score = bias +4.152
          + weight  +0.191 x feature  370 (average) =  -0.346
          + weight  -0.167 x feature 2016 (spread ) =  +0.262
          + weight  +0.259 x feature  903 (average) =  +0.242
          + weight  -0.213 x feature   20 (average) =  -0.223
          + weight  -0.158 x feature  902 (average) =  -0.204
          + 2043 more terms
    ---------------------------------------------
    raw score = +12.195

  Evidence pushing towards SYNTHETIC: +30.4
  Evidence pushing towards HUMAN     : -22.3
  Net                                : +12.2   (synthetic side)

  Of the total decision weight, 55% sits on the AVERAGE half
  and 45% on the SPREAD half. Both matter.

==============================================================================
STEP 4 · TURN THE SCORE INTO AN HONEST PROBABILITY
==============================================================================
The raw score +12.19 means nothing to an operator. The calibrator was fitted on
held-out clips: it looked at every score and recorded what fraction of clips at that
score were really synthetic. It is a lookup table, so 0.8 genuinely means 80%.

  raw +12.195  ->  P(synthetic) = 0.99

  a few other scores, through the same table:
    raw  -20  ->  0.01
    raw  -10  ->  0.01
    raw   -5  ->  0.01
    raw   +0  ->  0.53
    raw   +5  ->  0.99
    raw  +10  ->  0.99
    raw  +20  ->  0.99

  There are 8 of these tables, one per audio length, because a score from 1.5
  seconds and a score from 4 seconds do not mean the same thing.

==============================================================================
STEP 5 · THE GATE DECIDES WHETHER TO SPEAK
==============================================================================
  commit SYNTHETIC if P >= 0.85
  commit HUMAN     if P <= 0.15
  anything between is the undecidable band: DEFER, and escalate to the ladder
  and never before 1.5 s of audio, and only if the score held steady for 3 updates.

  P = 0.99  ->  SYNTHETIC

==============================================================================
SUMMARY OF THE WHOLE JOURNEY
==============================================================================
  64,000 audio samples
    -> 199 frames x 1024 learned features   (frozen model, 300M numbers, unchanged)
    -> 2048 numbers                     (average and spread)
    -> 1 raw score  +12.19              (our 2,049-number classifier)
    -> 1 probability 0.99                (calibrator)
    -> SYNTHETIC                        (gate)
